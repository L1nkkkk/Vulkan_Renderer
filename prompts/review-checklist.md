# Review 检查表

适用：`/review <文件>`。先确认 Task 编号、文件归属与审查范围，再按下表检查。遵守 [角色规则](README.md)；不修改代码，不提供受保护内容的可粘贴实现或伪代码。

## 审查步骤

1. 阅读目标文件及理解它必需的直接调用方、接口和资源创建 / 销毁路径。
2. 记录用户期望的行为；信息不足时用问题明确约束，不凭空补齐设计。
3. 对照下面各项检查。只报告有代码证据的问题；不适用项注明不适用，无法确认项说明缺少的证据。
4. 涉及 Vulkan 行为时附官方规范或指南链接，并核对当前启用的 API、feature 与 extension。
5. 输出问题清单及覆盖范围，不自动修复，不代写 docs 下的设计 / review 文档。

## 通用检查

| 检查项 | 需要核对的证据 |
|---|---|
| 分工 | 用户接口是否先于生成实现，受保护区域是否保持用户所有 |
| 接口契约 | 输入约束、错误行为、可重入性、资源所有权是否明确 |
| 功能 | 实现是否符合当前 Task 的行为目标与用户意图 |
| 错误路径 | 失败返回、提前退出、部分初始化与重建后的状态是否可解释 |
| 生命周期 | 创建、引用、最后使用、回收与销毁之间是否有充分的完成依据 |
| 数据契约 | CPU / shader 数据布局、范围、对齐和索引是否一致 |
| 证据 | 问题对应的路径、行号、调用条件与可观察影响是否齐全 |

## 按 Task 选择检查重点

| Task | 重点 |
|---|---|
| 00 | 可复现构建、SDL3 稳定版本与 vcpkg baseline、无重复 SDL2 依赖、最小窗口启动 / 关闭、shader 编译路径、工作目录 |
| 01 | SDL3 surface 接入与事件、窗口像素尺寸和 surface capabilities、帧资源复用、WSI 相关对象复用、异常返回、resize / 最小化、layout 与提交范围 |
| 02 | PSO 状态覆盖、dynamic rendering 格式、dynamic state、shader 数据契约、深度附件、BDA 生命周期 |
| 03 | descriptor layout / pool / set / 更新、UBO 多帧访问、纹理范围、每条 barrier 的实际生产者与消费者 |
| 04 | 用户先做自己的 review；agent 不能提供三个现成问题替代用户作业。受邀讨论时核对材质归属、排序适用范围、延迟销毁、ImGui 核心与 SDL3 / Vulkan 后端版本及生命周期 |
| 05 | pass 依赖、shadow map 写读关系、计时查询支持、有效位 / 单位、结果可用性、查询槽复用 |
| 06 | 捕获与结论是否对应、实验条件是否可比、RHI 引用版本与代码位置；仅事实校对，不补写观点 |
| 07 | 接口是否表达用户意图、后端是否满足契约、跨 API 假设、最小子集范围与不可支持情形 |

## 输出格式

先列真实问题，每条包含：严重程度、文件与行号、触发条件、实际影响、依据，以及需要用户回答或验证的问题。严重程度可用“阻断 / 高 / 中 / 低”，不要把纯风格偏好当作正确性缺陷。

最后简述已检查的范围与仍缺的运行证据。没有可确认问题时直接说明，不为了凑数制造缺陷。对 docs 的事实校对，修改后按 AGENTS.md 追加日期和修正数，不改措辞、不补观点。
